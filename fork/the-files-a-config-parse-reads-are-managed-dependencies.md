# The files a config parse reads are managed dependencies

- **Status:** carried
- **Upstream:** [agentgateway#3751](https://github.com/agentgateway/agentgateway/issues/3751) (issue, 2026-10-02): on upstream `main` @ `c7ac602e` a `backendTLS` file under a backend reference's own `policies` (an `extAuthz` target, a Substrate policy) is not tracked, reproduced with a rotation test against a route backend's as control; our PR [agentgateway#3794](https://github.com/agentgateway/agentgateway/pull/3794) (branch `upstream/parse-time-file-dependencies`, `4bf67110`) was closed in favour of [agentgateway#3863](https://github.com/agentgateway/agentgateway/pull/3863), merged 2026-10-08 as `0a8476fe` with our sign-offs; #3751 stays open until upstream closes it (#37742 row 53). Upstream's design is the better one: the serde hook reads through the managed fetcher inside the load's scope (`parse_fetcher`), one read whose bytes are the ones cached and watched, where this patch reads each file twice (files-only, then managed) and a rotation between the two reads leaves the old certificate in the config with the new bytes in the cache, so no later event notifies. The `refresh_file` re-arm is no upstream gap: upstream has no periodic file re-read (files carry `next_refresh: None`), the 60 s poll is #20's own. Drops whole, with the previous row, at the re-pin onto a commit containing `0a8476fe`
- **Our commit:** `611793c3` (the commit of pull request #23, rebase-merged onto `giantswarm` as one commit; at the 2026-09-24 re-pin its parse hook was re-seated on upstream's new YAML parser, #3639; replayed clean at the 2026-10-05 re-pin; in release 2.1.2)

## Change

Make the files a config parse reads managed dependencies (`record_files_only_reads` around the deserialization in `NormalizedLocalConfig::from`, `ResourceFetcher::register_file_dependencies` inside the load's scope) and keep a managed file's periodic re-read armed after a watch event (`refresh_file`)

## Reason

a backend TLS file referenced only under a Substrate policy's `policies.backendTLS` is resolved by upstream's serde hook `de_from_local_backend_policy` with a files-only fetcher, outside the resource manager: no watch, no re-read, not active, re-read only when some other resource triggers a reload. kubelet rotates a gateway pod's two `podCertificate` bundles in separate syncs up to 90 s apart; the listener bundle's watch reloaded before the client bundle was written, and the client certificate expired in place ([giantswarm/giantswarm#37915](https://github.com/giantswarm/giantswarm/issues/37915)). #20 did not reach these files, and its periodic re-read stopped after a file's first inotify event. Lab reproduction on 2.1.1 with 1 h certificates: the egress pod's two bundles land in one kubelet sync and its reload follows both; the router's servicedns rotation runs about 90 s ahead of its podidentity one, its reload re-parses the config before the old client certificate expires, and it held three rotations for that spacing alone, which a 24 h lifetime does not promise . On 2.1.2 (Substrate 1.0.3 chart, 3600 s) kubelet wrote the four bundles in four separate syncs, 69 s to 3.5 min apart, and every write was followed by its own `resource changed, reloading` for that file about 300 ms later, the podidentity files included; the functional confirmation: the lab's `agents-test` passed 6/6 at 22:39Z after the previous certificates had expired at 22:35Z, with no `CertificateExpired` in the egress log and no egress-tunnel failure in the worker logs, and the router reloaded again on its next podidentity cycle (Substrate release-1.0 v1.0.3 pins 2.1.2; agent-platform#653 carries floor 1.0.3 and the platform's own 2.1.2 tags)
